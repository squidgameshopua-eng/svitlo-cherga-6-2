# SVITLO 2.0 — персональні адреси та нагадування

**Статус: перевірений прототип у окремій гілці. НЕ розгорнуто для користувачів.**

Поточний бот для черги 6.2 у `main` залишається без змін.
Бот у цій гілці не має запущеного сервера, Telegram webhook,
загальноукраїнських адаптерів операторів або бази даних у хмарі.

## Послідовність першого налаштування

1. Користувач відкриває /start у власному чаті або адміністратор
   запускає налаштування для групи чи каналу.
2. Обирає область, населений пункт, вулицю, будинок.
3. Оператор перевіряється за адресою. Якщо більше однієї черги,
   бот пропонує вибрати чергу або всі підтверджені черги.
   Не можна вигадувати прив'язку квартир чи під'їздів.
4. Після успішного підтвердження адреси
   `universal.onboarding.confirm_address` створює підписку.
5. Відразу відображається питання:

   **⏰ Чи нагадувати перед плановим відключенням електроенергії?**

   - Не нагадувати
   - За 5 хвилин
   - За 15 хвилин
   - За 30 хвилин
   - За 1 годину

6. Вибір обробляється `universal.onboarding.callback_choice`.
   У групі чи каналі вибір може змінювати лише адміністратор,
   права якого підтверджені через Telegram getChatMember.
7. Переїзд, додавання «Робота», «Лікарня», зміна черги:
   окремі підписки для кожного чату та адреси.

`lead_minutes=NULL` означає, що вибір не завершено.
`lead_minutes=0` означає, що користувач свідомо вимкнув нагадування.
Нагадування — додаткові до звичайних сповіщень про графіки,
аварії, зміни та скасування.

## Підтверджений добовий графік

- Нагадування планується на кожний початок окремого підтвердженого
  інтервалу ГПВ.
- Тижневий попередній прогноз НЕ породжує точних нагадувань.
- Змінився початок відключення — старе нездійснене нагадування скасовується.
- Офіційно підтверджена відміна — нагадування скасовується.
- Пустий або неповний відповідь API НЕ дорівнює скасуванню.
- Користувач вибрав «Не нагадувати» — завдання не створюються.
- Користувач змінив налаштування — майбутні завдання перебудовуються.
- Надіслане нагадування відзначається в базі, повтор не створюється.
- Помилка Telegram: задача повертається в чергу та повторюється.
- Після часу початку відключення застарілі нагадування не доставляються.

Вчасність залежить від моменту публікації ДТЕК, доступності джерела,
мережі, сервера та обмежень Telegram. **100% гарантії
«рівно за 5 хвилин» немає.**

Якщо ДТЕК опублікував графік уже після бажаного часу нагадування,
система може доставити його із запізненням до початку відключення
або користувач може отримати звичайне повідомлення про зміну графіка.
Не створювати повтор після початку відключення.

## Розмежування отримувачів

| Telegram | Налаштування |
|---|---|
| Особистий чат | Власник обирає адреси та нагадування |
| Група | Адміністратор змінює спільні налаштування |
| Канал | Адміністратор налаштовує через особистий чат із ботом |

Бот має бути учасником групи або адміністратором каналу
з правом публікувати повідомлення.
У особистому чаті людина повинна самостійно запустити бота,
інакше Telegram не дозволить надіслати перше повідомлення.

## Масштабування на всю Україну

Один токен Telegram може обслуговувати різні чати й адреси.
`locations` містить унікальні адреси, `subscriptions` —
незалежні налаштування та отримувачів,
`confirmed_starts` — підтверджені початки,
`reminders` — довговічну чергу завдань.

Дані адрес НЕ зберігаються в коді або історії GitHub.
Прототип використовує SQLite лише для одного процесу
на захищеному диску. Для загальноукраїнського продакшну потрібні:

- HTTPS webhook для Telegram, перевірка `secret_token`.
- Захищена PostgreSQL із резервними копіями, шифруванням,
  обмеженням доступу та термінами зберігання.
- Адаптери всіх операторів, визначення оператора за адресою.
- Кешування графіків за оператором і чергою, а не за числом користувачів.
- Планувальник не рідше ніж раз на хвилину, окрема черга відправлення.
- Ліміти Telegram: орієнтовно 30 повідомлень/с по боту,
  до 1 повідомлення/с на чат, 20 повідомлень/хв на групу.
  Затримки при великій кількості адресатів неминучі.
- Контроль повторних подій, 429 RetryAfter, моніторинг,
  відновлення після збою та перевірка прав адміністраторів.
- Можливість /pause, /resume, /delete, /settings;
  видалення персональних даних і політика приватності.
- Відміна нагадувань, якщо змінилася черга і підписку
  призупинено до підтвердження користувачем.
- Об'єднання повідомлень для кількох черг однієї адреси,
  щоб не турбувати людей повторними однаковими сповіщеннями.

GitHub Actions cron не може гарантувати точний п'ятихвилинний
інтервал запуску і не підходить як єдиний планувальник нагадувань.

## Код прототипу

- `universal/reminder_core.py` — SQLite, підписки, вибір часу, планування, скасування і lease/retry.
- `universal/onboarding.py` — п'ять Telegram inline-кнопок, права доступу, обробка вибору і відправлення завдань.
- `tests/test_universal_reminders.py` — незалежні отримувачі, часові вікна, вимкнення, скасування, повтори.
- `tests/test_universal_onboarding.py` — початкове питання, авторизація груп/каналів, перезапуск, помилки доставки.

**Важливо:** точно одна доставка не гарантується у випадку мережевого збою
між успішною відправкою Telegram і записом результату в базу даних.
Можливе повторення після timeout. Перед масштабуванням потрібна
політика ідемпотентності та додатковий моніторинг.
