# SVITLO — надійність бота для одного будинку

Цей варіант призначено для **одного будинку, усіх підтверджених черг ДТЕК за його адресою та одного Telegram-чату**. Він не містить особистих адрес у коді. Відмінний від експериментальної універсальної версії для всієї України.

## Що повідомляє бот

- Підтверджений графік ГПВ на сьогодні й завтра, коли є відключення.
- Окремий попередній тижневий прогноз — тільки за наявності чинних обмежень у регіоні.
- Зміни часу, додані та прибрані години, сума годин без світла.
- Одноразове повідомлення, якщо всі раніше оголошені відключення скасовані.
- Офіційні регіональні екстрені режими / ГАВ, якщо повідомлення точно стосується області чи Кривого Рогу.
- Після додавання приватної адреси: локальні аварії, ремонтні роботи та перевірка черги будинку.
- **Немає підтверджених відключень, нових даних або змін — немає повідомлень.**
- Усі повідомлення Telegram українською мовою.

Пріоритет: екстрені повідомлення, адресні аварії, скасування та зміни суточного графіка, новий графік, нагадування, тижневий прогноз.

## Нагадування: вимкнені за замовчуванням

Змінна репозиторію `REMINDER_MINUTES` у Settings → Secrets and variables → Actions → Variables:

| Значення | Поведінка |
|---|---|
| `0` або відсутня змінна | Нічого не нагадувати |
| `5` | Нагадування за 5 хв |
| `15` | За 15 хв |
| `30` | За 30 хв |
| `60` | За 60 хв |
| `5,15` (приклад) | Два окремі нагадування; рекомендовано обирати мінімально потрібне |

Нагадування не замінюють жодного з наявних повідомлень про графіки.
Точні нагадування створюються **лише з повного підтвердженого добового ГПВ**.
Попередні тижневі шаблони, неповні таблиці, відключення з позначкою «можливо» не створюють нагадувань.

Нагадування може бути надіслане тільки **протягом 60 секунд після бажаного часу**; після цього його пропускають. Після початку відключення старе нагадування не надсилається.
Якщо ДТЕК скасував чи змінив час до надсилання, бот використовує актуальні підтверджені інтервали, а не застарілу чергу завдань.

**Важливо:** GitHub Actions `cron` запитує перевірку кожні п'ять хвилин, але GitHub може запускати її із запізненням або пропускати. Насправді за 10–12 листопада зафіксовані інтервали між запуском у декілька годин. Тому налаштування «за 5 хв» — лише **best effort**, без гарантій. У разі затримки нагадування не буде доставлено взагалі, а не прийде через 50 хвилин.

Для гарантованих нагадувань потрібна інша схема хостингу та перевірені SLA. Поточний GitHub не підходить для обіцянки точної доставки за 5 хв.

## Автоматичне відстеження всіх черг будинку

Адреса зберігається тільки у Repository Secret `DTEK_ADDRESS_JSON`. Реальна адреса не записується в код чи повідомлення.

```json
{"city":"НАСЕЛЕНИЙ_ПУНКТ","street":"НАЗВА_ВУЛИЦІ","house":"НОМЕР_БУДИНКУ"}
```

Кожна перевірка:
1. Читає фактичний перелік черг у відповіді ДТЕК для будинку.
2. Порівнює його з попереднім успішно повідомленим переліком.
3. Якщо додано або вилучено черги, надсилає **одне повідомлення** зі змінами.
4. Без очікування підтвердження продовжує відстежувати **всі поточні черги** цього будинку.
5. Для кожної черги незалежно обробляє ГПВ сьогодні/завтра, тижневий прогноз, зміни, скасування і необов'язкові нагадування.

**Приклад:** раніше відстежували 6.2. ДТЕК підтвердив 5.1 та 6.2. Бот один раз повідомляє про додавання 5.1 і надалі публікує графіки обох черг.

**Приклад:** ДТЕК підтвердив лише 5.1. Бот один раз повідомляє про вилучення 6.2 і далі відстежує 5.1.

Якщо повідомлення про зміну черг не вдалося надіслати, наступна перевірка повторить його. Інші підтверджені графіки при цьому не блокуються.

**Неповна відповідь або невідома черга:** бот не вгадує, які черги зникли. У цій перевірці він не публікує адресно прив'язані графіки.

**Без секрету адреси:** немає можливості перевіряти черги будинку. У цьому випадку зберігається старий режим спостереження за однією чергою `DTEK_GROUP`.

`DTEK_GROUP` є лише початковою чергою для зіставлення на першому запуску. Коли адреса доступна, список черг визначається тільки ДТЕК. Змінну `QUEUE_APPROVAL` більше не використовуємо.

Якщо за одним будинком є кілька черг, а відповідність окремих квартир чи під'їздів невідома, бот не визначає самостійно, кому належить конкретна черга. Тому він публікує інформацію про **всі черги будинку**.


## Захист від дублювання та помилок

- Контрольні суми та статуси відправлених повідомлень зберігаються без приватної адреси у `bot_state.json`.
- Успішно доставлені повідомлення зберігаються навіть коли наступне повідомлення в тому самому запуску завершилося помилкою.
- Telegram HTTP 429: враховується `retry_after`. Довге очікування не блокує процес нескінченно.
- Один вихідний чат — максимум приблизно одне повідомлення на секунду.
- Оновлення із втраченими/незрозумілими даними не сприймається як скасування.
- Стара історія станів очищається після 21 дня.
- Telegram не забезпечує для `sendMessage` ідемпотентний ключ. Якщо Telegram надіслав повідомлення, але HTTP-відповідь загубилась, можливий дубль під час наступного запуску.
- Результат запиту ДТЕК і Telegram може бути недоступним, тому **гарантій 100% доставки немає**.

## Що НЕ переноситься з універсального прототипу

- Реєстрація довільних адрес по всій Україні.
- База даних для багатьох користувачів і чатів.
- Різні персональні налаштування в одній групі (один чат — одна загальна опція).
- Авторизація сотень адміністраторів та вибір міста в Telegram.
- Масова черга розсилки 25/сек і захист від сотень тисяч користувачів.
- Cloudflare Workers/D1, платні токени або сервери.

Це не помилка: бот є **однобудинковим і безплатним**, а не універсальним сервісом.
